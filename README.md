# funpay-token-plugin

Модуль для твоего FunPay-бота на Python.
Когда человек покупает токены, бот **заходит на твой сайт под твоим аккаунтом (Sashka)**, создаёт ключ на нужное количество токенов и отдаёт его покупателю в чат.

Покупателю аккаунт на сайте **не создаётся** — он получает только ключ.

## Как это работает

```
FunPay → покупатель купил/написал → твой бот ловит сообщение
      → handle_purchase(...)          ← тут работает этот модуль
          1. понял, сколько токенов купили («2кк» → 2 000 000)
          2. если меньше 10 млн (refund_below) → АВТОВОЗВРАТ, ключ не создаётся
          3. зашёл на сайт под твоим аккаунтом (Sashka)
          4. создал ключ на столько токенов
          5. вернул сообщение с номером заказа и ключом → бот шлёт покупателю
```

Сообщения — обычный текст (без Markdown), в Telegram отображаются нормально:
эмодзи, переносы строк, всё на месте.

Пример сообщения покупателю:

```
✅ Оплата получена!
📦 Заказ: fp_3001
💰 Сумма: 20 000 000 токенов
🔑 Ваш ключ: DRYRUN-20000000-BEZMAJ
```

Пример при автовозврате:

```
❌ Заказ отменён, оформляем возврат.
📦 Заказ: fp_3002
💰 Сумма: 2 000 000 токенов
ℹ️ Минимальная сумма покупки — 10 000 000 токенов.
Деньги вернутся на ваш способ оплаты автоматически.
```

## Автовозврат (меньше 10 млн)

В `config.yaml`:

```yaml
refund_below: 10000000        # если куплено меньше — автовозврат
```

Что делает модуль при покупке меньше минимума:
- ключ **не создаётся**
- вызывается `site.refund()` (если настроен `refund.path`) — POST на твой сайт с номером заказа, суммой и покупателем
- покупателю уходит сообщение про возврат
- `result.admin_note` содержит текст для уведомления тебя (админа)

Если `refund.path` пустой — модуль только шлёт сообщения, а сам возврат
делает FunPay/платёжка (ты подтверждаешь его вручную в админке).

Возвращаемые флаги:
- `result.refund == True` — сработал автовозврат
- `result.order_id` — номер заказа
- `result.admin_note` — текст уведомления для тебя

## Установка

```bash
pip install -r requirements.txt
```

## Быстрый тест без сайта (dry-run)

```bash
python demo_live.py
```

`dry_run: true` (по умолчанию) ничего не трогает — ключ будет `DRYRUN-...`.

## Настройка

1. `config.yaml` — уже с твоим логином `Sashka`
2. Впиши `site.base_url` — адрес твоего сайта
3. Настрой эндпоинты под свою админку (`login`, `create_key`)
4. `dry_run: false` — модуль начнёт реально создавать ключи

### Сколько токенов даёт лот

Если у лотов фиксированное количество — пропиши ID лота:

```yaml
amounts:
  lots:
    "123456789": 2000000   # лот «2кк токенов»
```

Если количество пишется в названии/тексте («2кк», «500к», «2000000», «2.5 млн») —
включено по умолчанию (`parse_from_text: true`).

## Встраивание в Telegram-бота

Где-то при инициализации бота:

```python
from token_plugin import TokenPlugin

plugin = TokenPlugin.from_config("config.yaml")
```

В обработчике новой покупки/сообщения:

```python
result = plugin.handle_purchase(
    order_id="fp_12345",             # ID заказа FunPay — защита от повторной выдачи
    buyer_username="Иван2024",       # юзернейм покупателя на FunPay
    item_name="2кк токенов",         # название лота (или передай lot_id)
    message_text="хочу 2кк",         # текст сообщения, если количество в нём
)

# Telegram: шлём обычным текстом, parse_mode не нужен
if result.message:
    await bot.send_message(chat_id, result.message)

# уведомление себе при автовозврате
if result.admin_note:
    await bot.send_message(ADMIN_CHAT_ID, result.admin_note)

if not result.ok:
    log.error("Ошибка выдачи ключа: %s", result.error)
```

`result.duplicate == True` — этот заказ уже обрабатывался, повторно ключ не создаётся.

## API-контракт сайта

| Запрос | Метод | Ответ |
|---|---|---|
| `/api/login` | POST (логин, пароль) | 200 = ок |
| `/api/keys/create` | POST `amount`, `username` | `{"key": "ABC-123"}` |
| `/api/refund` | POST `order_id`, `amount`, `username` | 200 = ок |

Имена путей и полей полностью настраиваются в `config.yaml`.

## Правила безопасности

- `config.yaml` содержит пароль от сайта → **не заливай его в git**
- `config.yaml` уже в `.gitignore`
- Ставь `dry_run: false` только после успешного прогона `demo_live.py`
